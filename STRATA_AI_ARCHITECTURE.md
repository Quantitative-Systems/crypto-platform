# STRATA — AI Architecture & Safety Boundary Specification

## 1. Executive Principle
**AI Safety Invariant**: Artificial intelligence and machine learning models in STRATA operate strictly within assistive, analytic, and research domains. Under **no circumstances** does an LLM or unconstrained stochastic model execute direct live market orders, alter deterministic risk invariants, modify the frozen KING core, or bypass order reconciliation.

## 3. Detailed Component Architecture

### 3.1 Natural Language Strategy Compiler (`strategy/lab/strategy_lab_engine.py`)
- **Function**: Parses unconstrained trader descriptions into formalized JSON `StrategySpecification` models.
- **Rules Enforced**:
  - Validates instruments against the approved `CryptoUniverseManager` (BTC, ETH, SOL, BNB).
  - Enforces minimum reward-to-risk targets ($\ge 4.0\text{R}$).
  - Automatically identifies entry criteria, structural invalidation points, and stop levels.
  - Rejects ambiguous or untestable prompts with clear falsification guidance.

### 3.2 Research Evolution Engine (`execution/agent/research_evolution_engine.py`)
- **Function**: Continuously tracks live/paper execution metrics against historical baselines.
- **Capabilities**:
  - Detects performance degradation (Sharpe drift, win-rate decay, slippage surges).
  - Emits automated quarantine signals when strategy metrics breach tolerance bands.
  - Spawns asynchronous offline research experiments to test alternative parameters or hypotheses.
- **Safety Boundary**: The engine **cannot mutate running live production code**. Any candidate strategy generated by research must pass the complete 16-stage lifecycle before paper qualification.

### 3.3 Strata Autonomous Agent (`execution/agent/strata_autonomous_agent.py`)
- **Function**: Deterministic state machine coordinating qualified strategies across user accounts.
- **Execution Loop**:
  1. `OBSERVE`: Polls real-time market data across admitted instruments.
  2. `SELECT`: Evaluates opportunities against the selected `TradingStyle` (e.g., SWING, INTRADAY, AUTONOMOUS).
  3. `VALIDATE`: Queries `AccountSuitabilityEngine` and `RiskGovernor` for position sizing and leverage compliance.
  4. `MONITOR`: Tracks order fills, slippage, and position drift.

## 4. Deterministic Guardrails (Non-Negotiable)
1. **Zero LLM in Execution Critical Path**: Market order generation and cancellation logic is 100% deterministic Python code.
2. **Deterministic Risk Bounds**: $\le 1.00\%$ risk per trade, $\le 3.00\%$ portfolio heat, $\$0.00$ default capital limit.
3. **Protected Core Immutability**: The KING Engine cannot be modified by any AI assistant, prompt, or self-optimization agent.
